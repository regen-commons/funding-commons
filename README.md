## Project workspaces

Anyone can create a project with a name, description, total funding goal, currency and tags. Optional eligibility context distinguishes work countries, benefit countries, applicant base, legal registration and the actual applicant type. Benefit countries are never inferred from activity locations or global membership. Existing version 2 profiles receive unknown/empty defaults without changing saved IDs. Programme-condition answers are validated and included in local backups. Renaming preserves them; changing description, tags, goals or eligibility context clears them so an earlier proposal is not silently reused. Answers never enter embeddings or shared URLs. A project owns its saved list. Editing its details keeps its favorites; removing it moves its funds to General. New visitors start without predefined organization profiles.

Selecting a project ranks all 699 records for its description and tags. Keyword ranking works immediately; local AI is optional. Application access, name and deadline sorts remain available. Funding goals inform award explanations but do not impose eligibility or total-goal exclusions.

The directory retains search, theme/region/access filters, research-depth and primary-research filters, 24-card load-more navigation, native fund dialogs, two-to-four-fund comparison and deep links using `?fund=<source-id>`.

## Local semantic matching

The user-approved runtime is pinned to Transformers.js 4.2.0, ONNX Runtime Web 1.26.0-dev.20260416-b7804b056c and esbuild 0.28.1. The model is [Mixedbread mxbai-embed-xsmall-v1](https://huggingface.co/mixedbread-ai/mxbai-embed-xsmall-v1), revision `b0561d9a97e6b298da39f0ef3e7d3cf153b1b29a`, Apache 2.0. It is an English embedding model, not a chat model. The model card and license notices are retained in `research/` and bundled assets.

Following the [Artizen reference](https://github.com/Oba-One/artizen-fyi/tree/find-funds-for-upstream) at commit `da744982700eab124c707b300ecc30f9b59c1a48`, public fund vectors are generated before deployment and a browser worker embeds only the visitor’s project. This implementation uses single-threaded WebAssembly to work without GPU support or cross-origin-isolation headers. It explicitly constructs the pinned BERT tokenizer because Transformers.js v4 remote file discovery cannot inspect a local HTTP model directory with remote loading disabled.

The release has 768 program/overview documents across all 699 funders. Each named program gets its own vector; records without researched programs retain an overview vector. Every document uses the same model, quantized weights, mean pooling and 256-dimensional truncation followed by normalization. A release manifest records the exact corpus hash, text hashes, IDs, model contract and binary checksum. Any corpus/model/coverage mismatch prevents semantic matching; partial model results never mix with keyword scores.

Each program corpus entry uses that program’s focus and beneficiaries, with the funder mission as fallback when program topics are absent. It never combines sibling program topics. Overview records prefer verified mission over directory themes and funding approaches. Directory tags provide the fallback where official thematic evidence is missing. Historical project assessments, applicant exclusions, availability prose and private notes are excluded. Records with no thematic data receive zero relevance and remain visible for manual research. Records identified as other funding resources follow possible grantmakers without being hidden. Project names, goal amounts and applicant identifiers are excluded from the embedding query; descriptions and tags define the subject.

Local AI is opt-in and downloads about 40 MB of public model/runtime/index assets from the same Site. The 24.4 MB weights and each tokenizer/config file are checksum-verified before use, including cache hits. All model fetches are restricted to this origin and revision. CSP blocks outbound inference connections. Cache denial does not block inference. Public model files may remain cached; project embeddings are held only in worker memory and discarded when stopped. Profile data remains in the existing local browser store and user-requested backups. No model preference or query vectors are persisted.

Cards, fund details and comparison show a thematic-fit grade from 0 to 100, separately from readiness. Fit uses the stronger supported signal: a specific shared-term rubric or a local semantic-similarity rubric. Related forms such as culture/cultural and art/arts count once; broad organizational language is excluded. Shared terms grade 30, 50, 65, 75, 80 and 85 for one through six-or-more distinct specific terms. Semantic grades interpolate cosine anchors 0.25→0, 0.35→40, 0.45→60, 0.55→80, 0.70→95 and 1.00→100. Sparse purpose evidence caps thematic fit at 59; missing/broad-only focus is unassessed rather than a fabricated zero. Bands are Strong (80–100), Relevant (60–79), Partial (40–59), and Limited (below 40). These are explicit heuristic evidence bands, not measured probabilities, percentages of requirements met, or directory-wide accuracy estimates. Human-reviewed calibration is still needed. The rubric is authoritative in `dist/matching.mjs#THEMATIC_FIT_RUBRIC`; the details dialog renders those same values.

Readiness describes the next practical check: a known conflict, missing profile data, unconfirmed prerequisites, funding-type compatibility, stale sources, or the application route/timing. Geography, applicant status, budgets, funding preferences, deadlines and prerequisite answers do not change thematic fit. They continue to control shortlisting. The internal research-priority calculation retains the previous program-purpose, geographic, access and award components, preserving source-backed safeguards and actionability ordering. It is no longer the headline fit number. Equal thematic grades can have different priorities, and the result order explicitly says next-step priority.

A sourced conflict or funding-type preference mismatch holds the score at zero; the latter is not an eligibility exclusion. Missing local scope, unconfirmed geographic conditions or nonoverlapping geographic priorities cap scores at 24. Non-exhaustive country mentions lower priority but never create a hard exclusion. A program naming specific work countries needs project locations before shortlisting. Unconfirmed mandatory conditions cap scores at 39; required applicant models, leadership, history and partner arrangements cap them at 29. Weak topic evidence is capped at 24. Broad organizational language alone cannot establish a specific match; sparse shared topics need strong semantic evidence or strong lexical coverage. Closed calls cap at 19; future, invitation, relationship, mixed/unverified funding types and explicit limited funder capacity cap at 29. Missing or stale program evidence caps at 39. Overview-only records and unavailable screening data remain provisional, capped at 29. The most restrictive limit wins. Ties prefer purpose fit, then application access and stable alphabetical/record order. Details show every component and limit; comparison and CSV use the same selected program and score.

Project funding types are optional: grants, prizes, investment, fellowships and scholarships. Empty preferences preserve the previous all-types behavior, including old profiles and backups. Mixed offers require confirmation rather than being assumed to include a selected type. Optional US work states and US beneficiary states are separate; cities, counties and community boundaries still need source-backed local checks. All profile fields remain local and outside embedding queries.

Project-fit browsing starts with Research leads: at least 60 thematic-fit points, at least 30 internal research-priority points, purpose evidence and an open, rolling or inquiry route. These are conditional research leads, never eligibility approvals. Match view also exposes candidates needing checks, limited-relevance records, conflicts/preference mismatches and the full 593-record directory. Saved lists and their exports bypass this view filter. A zero-lead result provides access to candidates needing checks rather than inventing a strong match.

Cancellation terminates the worker and its downloads. Rejected initialization can be retried with a new worker. Request epochs and worker identity checks discard late results after profile switches, cancellation or recovery. A three-minute watchdog returns to keyword mode if download/inference never finishes. Model support, network, integrity or initialization failures preserve the full directory, favorites, comparison and exports.

Only explicit exhaustive requirements and exclusions can flag a conflict. A sponsor’s applicant status should be supplied when the sponsor is the actual applicant. Known conflicts move below other research leads, without hiding records. Inquiry routes have a separate filter and amber badge; they never appear under Open or rolling. A smaller grant can fund part of a total fundraising goal; different currencies are never silently converted. The 36-column CSV includes matching context, research depth, all retained official sources, named program terms/deadlines and source-integrity concerns while retaining every selected saved ID. A smaller grant may contribute to a larger total goal; each named program receives a separate award explanation.
